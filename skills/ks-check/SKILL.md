# 구현 검수

대상: $ARGUMENTS

- 작업 방식: 이 스킬 폴더 기준 `../../docs/workflow.md` — 시작할 때 한 번 읽는다
- 하네스: `node <플러그인 루트>/scripts/pp.mjs` (플러그인 루트 = 이 스킬 폴더의 두 단계 위)
- 검수 에이전트: `harness-kit:ks-checker` (읽기 전용)

## 1. 지켜야 할 것

- **검수하지 않고 "다 됐다"고 하지 않는다.** 검증 명령을 실제로 돌린 결과와 검수 표가 있어야 완료다.
- 판정은 검수 에이전트가 한다. 코드를 짠 이 대화가 스스로 충족을 주지 않는다.
- 고치는 것은 `부족`으로 나온 항목만 한다. 스펙에 없는 기능을 더하지 않는다.
- 스펙이 틀렸다고 보이면 코드를 스펙에서 벗어나게 고치지 않는다. 사용자에게 묻고, 스펙을 고치면 `/ks-dev`로 돌아간다.
- 작업 체크(`pp.mjs done`)는 그 작업이 `충족`일 때만 단다.

## 2. 대상 정하기

1. `.harness/config.json`이 없으면 `/ks-setup`을 먼저 하자고 알린다. 사용자가 그냥 하자고 하면 검증 명령만 물어 진행한다.
2. 대상이 기능 이름이면 `docs/product/{기능}/dev.md`, 경로면 그 파일을 쓴다.
3. 비어 있으면 `.harness/progress.md`의 하고 있는 일, 그리고 체크 안 된 작업이 남은 `docs/product/*/dev.md`를 후보로 보여 주고 고르게 한다.
4. 개발 스펙이 없는 작은 작업이면 **가벼운 검수**로 간다 (5장).

## 3. 검수 루프

1. `pp.mjs tasks <dev.md>`로 작업과 검증 목록을 받는다.
2. 이번에 검수할 범위를 정한다. 기본은 체크 안 된 작업 전부와 그 작업이 속한 단계의 검증 항목이다. 범위를 한 줄로 알린다.
3. **검증 명령**을 config의 `verify` 순서대로 돌린다.
   - 결과를 `baseline`과 비교한다. 원래 실패하던 것은 `기존 실패`, 새로 실패한 것은 `새 실패`로 나눈다.
   - 새 실패가 있으면 검수 에이전트를 부르기 전에 그것부터 보고한다.
4. **검수 에이전트**를 부른다 (`Agent`, subagent_type `harness-kit:ks-checker`). 넘길 것:
   - 검수할 T·V 목록 (tasks 결과 그대로)
   - 그 작업의 `근거:`가 가리키는 계약(C)·오류(E)·데이터(M) 원문 (dev.md에서 잘라서)
   - 비교 기준 커밋과 `git diff --stat` (기준: 브랜치를 땄으면 갈라진 곳, 아니면 마지막 /ks-handoff 커밋)
   - 검증 명령과 방금 결과 요약
5. 돌려받은 표를 사용자에게 보여 준다 (4장 모양).
6. 판정에 따라:
   - 모두 `충족` 또는 사람이 확인한 `확인 불가` → 6장으로 간다.
   - `부족`이 있으면 고칠 목록을 보여 주고 고칠지 묻는다. 고치면 3으로 돌아간다.
   - `확인 불가`는 사람이 확인할 방법을 알려 주고, 확인했다는 답을 받으면 충족으로 친다.
7. 같은 항목이 **3번 연속 부족**이면 멈춘다. 지금까지 시도한 것과 막힌 이유를 정리해 사용자에게 넘긴다.

## 4. 보고 모양

```text
검수  post-edit · T2, T3 · 2번째
검증  npm test  42 통과 / 2 기존 실패 / 새 실패 0

| 번호 | 판정 | 근거 | 부족한 점 |
|---|---|---|---|
| T2 | 충족 | posts.service.ts:41 | |
| V2 | 부족 | posts.service.ts:55 | 댓글 유지 테스트 없음 |

다음  V2 테스트를 추가하고 다시 검수할까요?
```

## 5. 가벼운 검수 (개발 스펙 없는 작은 작업)

1. 사용자가 시킨 일을 한 줄로 다시 적고 맞는지 확인한다.
2. 검증 명령을 돌려 기준선과 비교한다.
3. 검수 에이전트에게 그 한 줄과 diff를 넘겨 "시킨 일이 됐는지, 시키지 않은 변경이 있는지"만 판정하게 한다.
4. 결과를 보여 주고 6장으로 간다.

## 6. 끝

- 충족한 작업에 `pp.mjs done <dev.md> <T번호...>`로 체크를 단다.
- `.harness/progress.md`의 `마지막 검수` 칸을 날짜, 범위, 결과 한 줄로 고친다.
- 남은 작업이 있으면 다음 작업을 알리고, 없으면 그 기능이 끝났다고 알린다.
- 커밋은 하지 않는다. "정리하고 커밋하려면 /ks-handoff"라고 알린다.
