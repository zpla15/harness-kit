# 인계

남길 말: $ARGUMENTS

작업 방식: 이 스킬 폴더 기준 `../../docs/workflow.md` 5장.

## 1. 지켜야 할 것

- 기록은 대화가 아니라 파일에 남긴다. 다음 세션은 이 대화를 모른다고 보고 쓴다.
- 검수하지 않은 일을 끝났다고 쓰지 않는다. 검수 안 한 변경이 있으면 "검수 전"이라고 쓴다.
- 커밋, push, PR은 각각 묻고 한다. 팀 프로젝트에서 main에 바로 커밋하지 않는다.
- 진행 기록을 git에 올리지 않기로 한 프로젝트(`track: false`)는 `.harness/`를 커밋에 넣지 않는다.

## 2. 모으기

1. `.harness/config.json`, `.harness/progress.md`를 읽는다. 없으면 `/ks-setup`을 먼저 하자고 알린다.
2. `git status --short`, `git diff --stat`, 지금 브랜치, 마지막 인계 뒤의 커밋을 본다.
3. `docs/product/*/dev.md`마다 `pp.mjs tasks`로 남은 작업을 본다.
4. progress.md 맨 아래 `## 자동 저장` 칸이 있으면 읽는다. 대화가 압축되기 직전에 훅이 남긴 것이다.
5. 검수를 마지막으로 돌린 뒤 코드가 바뀌었으면, 커밋 전에 `/ks-check`를 할지 묻는다.

## 3. 진행 기록 쓰기

`.harness/progress.md`를 아래처럼 고친다. 모양은 `/ks-setup`의 템플릿과 같다.

| 칸 | 쓰는 법 |
|---|---|
| 지금 상태 | 하고 있는 일, 브랜치, 마지막 검수를 지금 기준으로 덮어쓴다 |
| 다음 할 일 | 다음 세션이 바로 시작할 일을 번호로 1~3개. 첫 줄은 명령째로 쓴다 (예: `/ks-check post-edit`) |
| 막힌 것·정할 것 | 사람이 답해야 하는 것, 원인을 못 찾은 실패 |
| 기록 | 표 맨 위에 한 줄 더한다: 날짜, 한 일, 커밋·PR |
| 자동 저장 | 위 칸에 반영했으면 지운다 |

- 기록 표가 30줄을 넘으면 오래된 줄을 `.harness/history.md`로 옮긴다.
- 남길 말이 있으면 `막힌 것·정할 것`이나 `다음 할 일`에 알맞게 넣는다.
- 고친 progress.md를 보여 주고 확인받는다.

## 4. 커밋

config의 `commit`을 따른다.

| 방식 | 하는 일 |
|---|---|
| main에 바로 | 커밋 메시지를 보여 주고, 확인받고 커밋한다. push는 따로 묻는다 |
| 브랜치 + PR | main이면 브랜치부터 만든다 (`feat/…`, `fix/…`). 커밋 → push할지 묻기 → PR 본문 초안을 보여 주고 만들지 묻기 |

- 커밋 메시지는 프로젝트의 기존 커밋 모양을 따른다 (`git log --oneline -10`).
- PR 본문에는 개발 스펙 경로, 끝낸 작업 번호, 검수 결과 표를 넣는다.

## 5. 끝

- 남긴 것을 세 줄로 알린다: 기록 파일, 커밋·PR, 다음 할 일 첫 줄.
- 컨텍스트가 길면 `/clear`를 권한다. 다음 세션은 훅이 진행 기록을 불러와 바로 이어진다.
